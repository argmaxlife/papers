# ViT-CoMer：用多尺度卷积特征增强 ViT 稠密预测

> **论文**：Chunlong Xia 等，*ViT-CoMer: Vision Transformer with Convolutional Multi-scale Feature Interaction for Dense Predictions*，arXiv:2403.07392v3（2024-03-27）。  
> **原文**：[arXiv:2403.07392](https://arxiv.org/abs/2403.07392)  
> **关键词**：Vision Transformer、CNN、特征金字塔、可变形注意力、目标检测、语义分割。

## 一句话概括

ViT 的全局建模和预训练迁移能力很强，但标准 ViT 通常只输出单一尺度特征，局部空间先验也较弱，不够适合检测、实例分割和语义分割。ViT-CoMer 保留可加载现成权重的 plain ViT，同时并联 CNN 多尺度分支：MRFP 为卷积特征增加多感受野表示，CTI 在多个 stage 通过多尺度可变形注意力双向融合 CNN 与 ViT 特征。方法不需要额外预训练，接上 dense prediction 框架并全量微调即可。

## 架构总览

输入图像同时进入两条分支。ViT 将图像切成 patch，产生 stride 16 的单尺度特征；CNN 逐层下采样，产生 stride 8、16、32 的特征金字塔。ViT 的多个 block 被划分为若干 stage，默认 `N=4` 次交互：

```text
图像 [B, 3, H, W]
  ├─ ViT patch embedding → X: [B, H/16 × W/16, D]
  └─ CNN backbone       → C3, C4, C5:
                           [B,D,H/8,W/8], [B,D,H/16,W/16], [B,D,H/32,W/32]
             ↓ 每個 stage
          MRFP → CNN 多尺度特征
          CTI  ↔ ViT 特征双向交互
             ↓
          输出多尺度特征供检测/分割头使用
```

ViT 直接加载 ImageNet、BEiT、DINOv2 等预训练权重；CNN 和新增交互模块随机初始化。因此这是“免额外大规模预训练”，不是冻结 ViT，也不是 adapter-only 训练：下游训练会端到端更新整个模型。

## MRFP：多感受野特征金字塔

令 CNN 的三个尺度特征为 `C3、C4、C5`，每个位置投影到通道维 `D`。将空间维展平并串接：

$$
C\in\mathbb{R}^{(HW/8^2+HW/16^2+HW/32^2)\times D}.
$$

MRFP 先降维，然后沿通道切成多组；不同组经过不同 kernel 的 depth-wise convolution（默认 3×3 和 5×5），最后拼接并升维。论文式 (1) 将其概括为：

$$
F=\mathrm{FC}\bigl(\mathrm{DWConv}(\mathrm{FC}(C))\bigr).
$$

以 `H=W=512`、`D=256` 为例：三层输入含 `64²+32²+16²=5376` 个位置，串接张量约 `[B,5376,256]`。较大卷积核扩大局部感受野，保留 stride 8 的细节、stride 32 的上下文，同时比在每组通道上做完整卷积便宜。MRFP 不是独立替代 CNN backbone，而是在其金字塔表示上增加多感受野处理。

## CTI：CNN 与 ViT 双向交互

ViT 特征 `X` 的空间分辨率是 `H/16 × W/16`，对应 CNN 的中尺度 `F4`。先将两者相加得到融合后的中尺度特征 `F4'`，再与 `F3、F5` 组成多尺度集合 `F'={F3,F4',F5}`。对该集合做 LayerNorm、多尺度 deformable attention 和 FFN：

$$
O=\mathrm{FFN}\bigl(\mathrm{Attention}(\mathrm{Norm}(F'))\bigr).
$$

这里 attention 的 token 来自 stride 8/16/32 三种尺度，不再局限于 ViT 单一 patch 网格。将 `O3、O5` 双线性 resize 到 `O4` 尺度后，形成供两分支回注的融合信息。

在第 `i` 个交互 stage 开始时，融合结果注入 ViT 分支：

$$
\hat X_i=X_i+\alpha O_{2i-1},
$$

其中 `α` 是可学习系数，初始化为 0。这样训练初期模型等价于原来的预训练 ViT，随机初始化的 CNN 不会突然扰动其表征；之后 `α` 学会逐渐利用卷积信息。stage 末尾以类似残差相加的方式把 CTI 输出注入 CNN 分支（论文式 (4)：`F̂_i=F'_i+O_{2i}`），使 CNN 也获得 ViT 的长程语义。作者将这两次注入称为 bidirectional interaction。

沿用上例，若 `B=2,H=W=512,D=256`，ViT tokens 是 `[2,1024,256]`；CNN 多尺度位置总数为 5376。CTI 中间表示将三个尺度共同送入多尺度 deformable attention；注意它通过稀疏采样位置做跨尺度交互，不是对全部 5376 个位置执行完整的 `5376×5376` dense self-attention。输出再按尺度还原，供 ViT 与 CNN 分支更新。

## 实验设置与结果

论文评估 COCO 目标检测/实例分割和 ADE20K 语义分割，采用 MMDetection、MMSegmentation 中的标准框架。默认比较常用 Mask R-CNN、UperNet 等；表格中的 `†` 表示 ImageNet-22K 预训练，`‡` 表示 DINOv2 预训练，无标记结果默认使用 ImageNet-1K 权重。

- **COCO Mask R-CNN，3× schedule**：ImageNet-1K 初始化的 ViT-CoMer-L 达到 box AP 52.9、mask AP 46.4；使用 DINOv2 初始化的 L 达到 55.9/49.1。相较 plain ViT-L、同规模 ViT-Adapter 等均有提升。
- **COCO 强检测器**：与 Co-DETR 结合时，BEiTv2 初始化的 ViT-CoMer-L 达到 64.3 box AP；作者报告未使用 Objects365 等额外检测训练数据。ImageNet-22K 初始化版本为 62.1 AP。
- **ADE20K UperNet**：ImageNet-22K 初始化的 ViT-CoMer-L 单尺度/多尺度 mIoU 为 54.3/55.6；多模态预训练版本为 56.3/56.8。
- **ADE20K Mask2Former**：ViT-CoMer-L 达到 61.7 单尺度、62.1 多尺度 mIoU，接近当时最佳模型。
- **消融**：ViT-S 基线 COCO box/mask AP 为 40.2/37.1；加 MRFP 后为 41.5/38.2；再加 CTI→ViT 后为 43.3/39.3；同时双向 CTI 后达 45.8/40.5。默认交互 stage 数为 4；MRFP 使用 3×3 与 5×5 两种 kernel 时最好。

## 结果如何理解

ViT-CoMer 的重点是保留 ViT 原有预训练接口，同时给 dense task 补上卷积的局部连续性与层级尺度。MRFP 先改善 CNN 分支的多尺度/多感受野表示；CTI 的 deformable attention 在多个尺度间融合信息，再双向更新两条分支。零初始化残差门控则让新增分支从不改变预训练 ViT 的初始行为开始学习。

结果也说明预训练质量是重要变量：同一架构用 DINOv2 或 BEiTv2 初始化，往往显著高于 ImageNet-1K 初始化。论文的最佳 64.3 COCO AP 使用 Co-DETR 与 BEiTv2 初始化；不能把它与普通 Mask R-CNN 的 55.9 AP 当作只由 backbone 架构造成的差异。检测/分割任务均对整个网络和任务头进行训练，方法本身不是无需下游微调的通用冻结特征。

## 局限与问题

- ViT-CoMer 额外增加一条 CNN 分支和 CTI 交互，参数量、显存和训练/推理成本都高于纯 ViT；论文强调效果，未提供统一硬件下全面的吞吐或延迟对比。
- 为达到最佳结果需要全量微调和高质量预训练权重，部署时仍要按目标任务选择并训练检测/分割框架。
- 最优 CNN 架构、交互位置和 stage 数可能依数据集与 ViT 规模而变化；消融主要在有限设置下完成。
- 主张集中在二维检测、实例分割和语义分割，其他 dense task、跨域迁移与极高分辨率效率仍需单独验证。

## 延伸问题

- 能否用冻结 ViT 加轻量 CTI 达到相近效果，以减少全量微调成本？
- 多尺度 deformable attention 的采样点与不同 CNN 感受野是否学到互补信息？
- 若把 CNN 分支换成 DINOv3 等强 dense backbone，收益是否仍来自局部归纳偏置，还是主要来自额外特征容量？
- 在精度相当时，ViT-CoMer 与 Swin、ViT-Adapter 等方法的实际端到端延迟和显存差异如何？

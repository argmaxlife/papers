# Vision Transformers Need Registers：论文阅读笔记

> **论文**：Timothée Darcet、Maxime Oquab、Julien Mairal、Piotr Bojanowski，*Vision Transformers Need Registers*，ICLR 2024。  
> **版本**：arXiv:2309.16588v2（2024-04-12）  
> **原文**：[arXiv:2309.16588](https://arxiv.org/abs/2309.16588)  
> **关键词**：Vision Transformer、register tokens、局部特征、异常高范数、无监督目标发现。

## 一句话概括

一些训练充分、规模较大的 ViT 会在低信息量的图像 patch 上产生少数异常高范数 token。这些 token 的局部信息较弱，却含有较强的全局图像信息。作者提出在 patch token 序列中增加可学习的 register tokens，让模型有专用位置进行全局计算；模型最终仍只使用 `[CLS]` 和 patch token 作为输出。这样能消除 patch 特征中的异常值，并改善若干稠密视觉任务与无监督目标发现结果。

## 研究问题与观察

DINOv2 的特征在深度估计、语义分割等稠密任务上很强，但直接用于依赖平滑局部特征的无监督目标发现（如 LOST）时效果不理想。作者在 DINOv2、DeiT-III 和 OpenCLIP 等 ViT 中观察到 feature map 上的异常点：少数 patch token 的输出 L2 范数远高于其他 token，常出现在平滑背景等信息冗余区域。

对 DINOv2-g，作者用范数大于 150 作为分析中的异常 token 判据，观察到比例约 2.37%。该阈值是针对模型的手工阈值，不是通用定义。异常 token 大约从 40 层模型的中间层开始出现，训练到约三分之一后变得明显，且主要出现在 Large 及更大模型中。对异常 token 的线性探测发现，它们较难预测 patch 位置或重建原始像素，但单独用于图像分类时比普通 patch token 更有效。作者据此推测它们保留了全局信息、丢失了较多局部信息。

## 方法：把隐式工作区显式化

ViT 将图像切成 patch 并映射为 token。若图像有 `P` 个 patch、隐藏维度为 `d`，常见输入序列可写成：

```text
patch tokens: [P, d]
[CLS] + patch tokens: [P + 1, d]
```

作者在 patch embedding 后插入 `R` 个可学习 register 向量：

```text
输入序列: [CLS, REG_1, ..., REG_R, PATCH_1, ..., PATCH_P]
张量形状: [1 + R + P, d]
```

例如 `P=196`、`R=4`、`d=1024` 时，Transformer 输入形状为 `[201,1024]`。register 向量像 `[CLS]` 一样是模型参数，但不承载额外图像输入。经过多层自注意力后，register 能与所有 patch 交换信息：它们可以聚合图像全局信息，再在后续层中被其他 token 读取。这里没有要求某个 register 对应某个物体，也没有专门的 register loss。

输出端丢弃 register token，只保留 `[CLS]` 与 patch token：

```text
Transformer 输出: [1 + R + P, d]
下游表征: [CLS] 和 patch tokens，形状 [1 + P, d]
被丢弃: R 个 register 输出
```

这点很关键：register 是模型内部的临时工作区，不是新的分类标签、检测 query 或最终特征。若下游需要空间特征，就使用还保留图像局部对应关系的 patch token。

## 为什么会消除异常 patch

自注意力层允许任意 token 读取其他 token 的信息。作者的解释是：模型原本会在缺乏局部内容的 patch token 上“回收”计算位置，把某些 patch token 当作内部寄存器，累积或传递全局信息；其副作用是这些位置不再像普通 patch 一样表示本地像素内容，于是范数异常、feature map 不平滑。增加专门的 register 后，模型可以把这类计算转移到 register 上，patch token 因而保留更干净的局部表征。

这是与实验一致的机制假说，而不是论文已完全识别出的因果过程。直接证据包括：异常 token 的范数分布、位置/像素探测能力下降、分类信息更强，以及加 register 训练后异常范数消失、局部任务表现改善。作者也观察到一些 register 的注意力图会关注图像中不同区域，但并未证明每个 register 稳定对应某种语义角色。

## 实验设计与结果

作者将 register 改动分别用于三种训练方式：ImageNet-22k 上的 DeiT-III 监督训练、Shutterstock 图文数据上的 OpenCLIP 图文监督训练，以及 ImageNet-22k 上的 DINOv2 自监督训练。报告的主对比是冻结特征上的线性评估：

| 模型 | ImageNet Top-1 | ADE20k mIoU | NYUd RMSE ↓ |
|---|---:|---:|---:|
| DeiT-III | 84.7 | 38.9 | 0.511 |
| DeiT-III + registers | 84.7 | 39.1 | 0.512 |
| OpenCLIP | 78.2 | 26.6 | 0.702 |
| OpenCLIP + registers | 78.1 | 26.7 | 0.661 |
| DINOv2 | 84.3 | 46.6 | 0.378 |
| DINOv2 + registers | 84.8 | 47.9 | 0.366 |

register 不会明显损害分类质量；DINOv2 在三项指标上均有所改善。OpenCLIP 的 ImageNet zero-shot Top-1 为 59.9，增加 register 后为 60.1，基本不变。作者注明其 OpenCLIP 复现使用的数据源不同于原始模型，因此绝对成绩较低。

在 DINOv2 ViT-L/14 的寄存器数量消融中，测试了 0、1、2、4、8、16 个 register。一个 register 已足以在可视化中消除异常点，增加到多个通常进一步有利于下游任务；不同任务的最佳数量不完全相同。论文多数实验使用 4 个。

在 LOST 无监督目标发现任务上，以 corloc 衡量，DINOv2 加 register 相较原模型在 VOC 2007 从 35.3 升至 55.4，在 VOC 2012 从 40.2 升至 60.0，在 COCO 20k 从 26.9 升至 42.0。DeiT-III 也大幅提升。OpenCLIP 的 LOST 分数反而略降，说明去除范数异常并不保证所有下游流程都变好；作者的中间结果分析认为 LOST 对 OpenCLIP 的这类异常较为鲁棒。

## 计算代价与实现注意

多出 `R` 个 token 会增加每层注意力的序列长度。对序列长度 `L=P+1` 的标准自注意力，其主要注意力计算随 `L²` 增长；增加 register 会引入额外计算，但其参数量相对 ViT 主干可忽略。论文测得 4 个 register 的 FLOPs 增幅低于 2%，16 个时最高约 6%。

作者还发现位置嵌入插值是否使用抗锯齿会改变异常 token 的空间条纹分布；他们在相关 DINOv2 实验中启用了抗锯齿插值。因此复现结果时，预处理和位置嵌入插值设置也需要一致，不能只比较是否添加 register。

## 结论与评价

这项工作的贡献是指出 ViT 局部特征中的高范数异常并提出一个简单有效的训练期结构改动。register 不直接增加图像信息，而是为 Transformer 提供专门的内部信息交换位置；最终下游表示仍由原来的 `[CLS]` 与 patch token 构成。结果尤其支持在需要平滑空间特征的稠密预测和无监督目标发现中使用 registers。

证据边界也值得记住：异常范数阈值依模型而异；“冗余 patch 被回收成内部寄存器”是解释性假设；数据与训练配方覆盖有限，且 OpenCLIP 的目标发现结果并未改善。工程上 register 很便宜，但它不会取代对注意力实现、分辨率、插值策略和下游任务的单独验证。

## 延伸思考

- register 数量是否应随 patch 数量、模型深度或任务类型动态变化？
- 能否用因果干预验证 register 是否接管了原本由异常 patch token 承担的全局计算？
- 在视频、医学影像或高分辨率遥感图像中，register 是否也能稳定改善局部特征？
- 对需要利用全局信息的下游任务，何时应保留 register 输出，何时应像本文一样丢弃？

# 稀疏门控 MoE：论文阅读笔记

> **论文**：Noam Shazeer 等，*Outrageously Large Neural Networks: The Sparsely-Gated Mixture-of-Experts Layer*（arXiv:1701.06538v1，2017）  
> **原文**：[arXiv:1701.06538](https://arxiv.org/abs/1701.06538)  
> **主题**：以条件计算扩大语言模型参数容量；按 token 选择少数前馈专家。

## 一句话概括

在普通 Transformer/语言模型的前馈子层里，不必让每个 token 都经过同一套参数，也不必激活全部前馈网络。让一个门控网络按 token 选择 top-k 个专家，再把专家输出加权合并，可以用接近固定的计算量换取大得多的参数容量。论文发表于 2017 年，实验架构是 LSTM 加 MoE，不是 Transformer；将它映射到现代 LLM 的 FFN，是理解其机制的方便类比。

## 背景与问题

稠密模型每个样本都会使用几乎所有层参数。增大参数量通常也增大每个 token 的计算量。MoE 将某一层替换为许多独立的前馈网络（experts）和一个小门控网络（gate）：参数总量随专家数增加，而单个 token 只计算其中 k 个专家。

论文还指出了稀疏路由的工程代价：专家收到的 token 批次变小，设备间传输可能成为瓶颈，而且门控可能反复偏爱少数专家。因此稀疏性本身不够，还要处理批次聚合、设备分片和负载均衡。

## 从 token 张量看 MoE

以下用 LLM 常见的形状举例。设批大小 `B=2`、序列长 `T=3`、模型宽度 `d=4`、专家数 `N=3`、每个专家隐藏宽度 `m=5`，每个 token 选 `k=2` 个专家。一个 MoE 子层接收：

```text
X: [B, T, d] = [2, 3, 4]
```

论文逐个位置计算 MoE。实现时可把 batch 和序列位置合并成 `S=B*T=6` 个 token：

```text
X_flat: [S, d] = [6, 4]
```

每个位置单独路由；token 之间不混合。处理完后再 reshape 回 `[B,T,d]`。若将 MoE 用作 Transformer FFN，通常输入输出宽度均为 `d`；注意力子层仍负责 token 间的信息交互，MoE 专家负责对每个位置的表示做变换。

## 公式逐项解释

### 1. 专家输出与加权合并

论文式 (1)：

$$
y = \sum_{i=1}^{N} G(x)_i E_i(x)
$$

`x` 是一个 token 的向量 `[d]`；`E_i` 是第 `i` 个专家，对应一套独立参数。以两层 FFN 为例：

$$
E_i(x)=W_{2,i}\,\mathrm{ReLU}(W_{1,i}x+b_{1,i})+b_{2,i}
$$

其中 `W1_i: [m,d]=[5,4]`、`W2_i: [d,m]=[4,5]`，所以 `E_i(x): [d]=[4]`。`G(x)_i` 是门控给第 `i` 个专家的标量权重。所有专家输出按这些权重求和，得到仍为 `[d]` 的 `y`。

对 `S=6` 个 token 批量计算时，概念上的全量专家输出形状是 `[S,N,d]=[6,3,4]`，门控权重是 `[S,N]=[6,3]`，加权求和后为 `[S,d]=[6,4]`。但稀疏实现不会真正算出全量 `[S,N,d]`：只计算每个 token 选中的专家输出，再 scatter-add 到对应 token 的输出行。

### 2. 稠密 softmax 门控

论文式 (2)：

$$
G_\sigma(x)=\mathrm{Softmax}(xW_g)
$$

`W_g: [d,N]=[4,3]`。对单个 token，`x: [4]` 乘 `W_g` 得到三个专家的 logits `[3]`，softmax 后的权重也为 `[3]`，总和为 1。对所有 token 批量计算：

```text
X_flat [6,4] @ W_g [4,3] -> logits [6,3]
softmax(logits, dim=-1) -> gates [6,3]
```

这种门控会让每个 token 使用全部 `N` 个专家，参数虽多，计算也随 `N` 增加，达不到稀疏条件计算的目的。

### 3. 带噪声的 top-k 门控

论文式 (3)-(5)：

$$
G(x)=\mathrm{Softmax}(\mathrm{KeepTopK}(H(x),k))
$$

$$
H(x)_i=(xW_g)_i+\epsilon_i\,\mathrm{Softplus}((xW_{noise})_i),\quad \epsilon_i\sim\mathcal{N}(0,1)
$$

`W_noise` 同样是 `[d,N]`。`Softplus` 产生正的噪声尺度；每个专家 logit 加上独立高斯噪声。`KeepTopK` 保留最大的 k 个值，其余置为负无穷。softmax 后，被屏蔽位置权重严格为 0，保留的 k 个权重和为 1。

例如，某 token 的带噪 logits 为 `[1.2, 0.4, 2.0]`，`k=2`：屏蔽后为 `[1.2, -∞, 2.0]`，softmax 约为 `[0.31, 0, 0.69]`。只需计算专家 1 和 3，输出为 `0.31 E_1(x)+0.69 E_3(x)`。在批量情况下，路由索引形状为 `[S,k]=[6,2]`，门控值为 `[6,2]`；专家按索引收集各自 token 子批次，处理后按原位置合并。

训练时，门控、被选中的专家和后续层通过反向传播联合学习。top-k 选择有离散边界，但保留专家的 softmax 权重对 logits 可导；噪声也让训练时专家选择更具探索性。

### 4. 专家重要性损失

对一个含 `S` 个 token 的批次，论文式 (6) 把每个专家收到的门控权重加起来：

$$
\mathrm{Importance}(X)_i=\sum_{s=1}^{S}G(x_s)_i
$$

因此 `Importance(X)` 是 `[N]` 向量。本例中为 `[3]`。若所有 token 总偏向同一专家，这个向量会不均匀。论文式 (7) 对重要性向量的变异系数平方加权：

$$
L_{importance}=w_{importance}\,\mathrm{CV}(\mathrm{Importance}(X))^2
$$

`CV(v)=std(v)/mean(v)`，故损失无量纲；均匀分配时接近 0。此项平衡的是门控权重总量，不保证每个专家实际收到的 token 数量一样。

### 5. 负载损失

实际负载是每个专家被 top-k 选中的 token 数，但硬计数不可微。论文用带噪门控估计某专家被选中的概率。式 (8)-(9) 可写成：

$$
P(x,i)=\Phi\!\left(\frac{(xW_g)_i-\mathrm{kth\_excluding}(H(x),k,i)}{\mathrm{Softplus}((xW_{noise})_i)}\right)
$$

`kth_excluding` 是忽略专家 `i` 后的第 k 大 logit；分子表示专家 `i` 的均值超过竞争阈值多少，分母是其噪声标准差；`Φ` 为标准正态 CDF。于是 `P(x,i)` 是 `[0,1]` 之间的近似入选概率。

将概率对 token 累加得到期望负载（式 (10)）：

$$
\mathrm{Load}(X)_i=\sum_{s=1}^{S}P(x_s,i)
$$

仍是 `[N]` 向量。式 (11) 对该向量的变异系数平方惩罚：

$$
L_{load}=w_{load}\,\mathrm{CV}(\mathrm{Load}(X))^2
$$

`L_importance` 让权重总量均衡，`L_load` 让每个专家预计处理的 token 数均衡。二者都加进主任务损失，并非替代语言模型的 next-token loss。

## 如何节省计算，以及代价

若每个专家是宽度 `m` 的两层 FFN，稠密地运行 N 个专家，单 token 的乘加量约为 `2Ndm`；top-k 路由约为 `2kdm`，另有门控和分发开销。当 `N` 很大而 k 固定，专家计算不随 N 成比例增长；但所有专家参数仍需存储、优化器状态也需保存。实际训练还要跨设备传送 token 表示和专家输出。

论文为扩大专家批次，将多个数据并行副本送来的路由结果聚合到共享专家上；对序列模型，则先收集多个时间位置再批量送入 MoE。专家网络需要足够大的矩阵计算，才能摊薄通信成本。论文也提出分层 MoE，以分级门控管理大量专家。

## 实验结果

- 在 1 Billion Word 语言模型任务中，作者构造计算预算相近的模型；包含 4096 个专家的模型，相较计算匹配基线测试困惑度降低约 24%。一个约 4.3B 参数的低计算 MoE 模型用约 8.9M ops/timestep，10 epoch 困惑度为 34.1；论文对照的既有模型有 151M 参数、151M ops/timestep，困惑度为 34.7。
- 在约 100B 词的内部新闻语料上，固定计算预算时，容量提升到 65,536 个专家（MoE 层约 68B 参数）仍改善结果，测试困惑度相较计算匹配基线降低约 39%；131,072 个专家时效果回落，作者认为可能是稀疏度过高。
- 单语对机器翻译中，8.7B 参数的 MoE 模型在 WMT'14 En→Fr 达到 40.56 BLEU、En→De 达到 26.03 BLEU，超过论文引用的 GNMT 基线。
- 多语翻译 MoE 在 12 个语言对中的 11 个 BLEU 高于多语 GNMT；英语到韩语是明显退化例子，作者将其与少样本过采样导致的过拟合联系起来。

## 从今天的 LLM 视角看

这篇论文确立了现代稀疏 MoE 的关键抽象：路由发生在 token 级别；专家是独立的 FFN；top-k 门控保持稀疏计算；辅助损失缓解专家利用不均。放进 Transformer 时，可以把普通 FFN 替换为专家池，而注意力仍处理上下文。以 `[B,T,d]` 隐状态为输入，路由器为每个位置产生专家选择，专家处理被分配到自己的 token 子批次，结果按 token 位置还原。

阅读这篇 2017 年论文时需要区分“参数容量”和“实际 token 计算”：MoE 扩大前者，不会自动让训练或推理便宜。路由、token 分发、负载均衡、设备通信、内存中的专家参数和优化器状态，都会影响端到端效率。论文使用 noisy top-k 和变异系数辅助损失；现代 MoE 系统在路由策略、容量限制、溢出 token 处理及并行实现上还有许多不同设计，不能把这些细节视为唯一方案。

## 阅读结论与问题

论文的主要贡献不只是“把 FFN 复制很多份”，而是把稀疏条件计算、负载正则和分布式批处理一起设计，使超大参数层能在当时的 GPU 集群上训练。它展示了大语料与高容量之间的互补性，也暴露了稀疏路由的系统复杂度。

后续值得追问：辅助损失权重如何影响主任务质量？专家负载均衡是否会与有意义的专家专化冲突？当专家分布在多个设备时，通信时间占端到端延迟多少？在自回归生成中，批次很小时，训练期间的批量吞吐优势还能否保留？
